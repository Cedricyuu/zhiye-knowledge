# Java 后端学习手册

这是一份供知页功能演示使用的示例资料。下面的约定用于说明文档检索与引用流程，不是某个真实公司的制度。

## Spring Boot 自动配置

Spring Boot 的自动配置会根据类路径上的依赖、已有的 Bean 和配置属性，为应用提供合适的默认配置。开发者添加 Web Starter 后，可以较少的配置搭建 Web 应用。需要定制行为时，可以通过配置属性或自己声明的 Bean 覆盖默认行为。自动配置不等于完全不需要配置。

## Controller、Service 与 Mapper

Controller 接收 HTTP 请求，校验输入参数，把业务操作交给 Service，并将处理结果返回前端。Service 组织业务规则、权限校验与事务。Mapper 使用 SQL 访问数据库。上传文档的调用流程可以表示为：页面选择文件 → Controller 接收文件 → Service 解析并切分文本 → Mapper 保存文档与文本片段。

## MyBatis 参数绑定

MyBatis 的 #{参数} 会通过预编译语句绑定参数值，能够避免把用户输入直接拼接进 SQL。${参数} 是文本替换，不能直接用于不可信输入。动态排序字段应使用白名单，而不是直接接收前端给出的 SQL 片段。

## 数据库事务

数据库事务的 ACID 特性分别是原子性、一致性、隔离性和持久性。上传文档时，文档记录和全部文本片段应在同一个事务中保存。如果片段写入失败，整个数据库操作回滚，避免出现一份看似成功却没有完整内容的文档。数据库回滚不会自动撤销外部 API 调用或文件系统写入。

## 用户资料隔离

用户资料隔离必须由后端执行。查询文档、检索文本、查看问答历史以及提交反馈时，都需要在数据库查询中限制 user_id。前端隐藏别人的文档不构成权限控制。检索必须先按当前用户筛选资料，再计算相关度，防止其他账号的内容进入回答上下文。

## RAG 与引用

RAG 的流程是先检索与问题相关的文档片段，再把片段作为上下文发送给语言模型生成回答。引用应保存文档名、片段编号、页码以及当时使用的原文快照。没有找到依据时，应明确说明资料不足，不能用无关片段拼凑答案。知页使用中文向量和关键词结合检索；只检索时返回原文，启用模型后会整理回答，并为每个要点给出可在资料中核对的摘录。

## 本示例的项目约定

示例项目代号为「青竹」。青竹项目的学习分享会在每周三 19:30 开始，地点为线上会议室。分享前需要准备一个接口演示和一个真实问题的排查记录。这些是测试检索效果的人造约定，不是现实活动安排。
